## Unreleased

## 1.0.0 - 2026-11-08

Initial public release.

### Added

- Importers: one class per record type (`Importer`) with typed fields (text, integer, decimal, boolean, date, date-time, email, choice, reference), labels in any locale, aliases, examples, normalisers and validation rules; an ordered natural key for duplicates; owner-scoped reference lookups; create, update, authorize and rollback callbacks. `key()` and `label()` default from the class name (`AssetsImporter` → `assets` / `Assets`); `Field::reference()->storeAs('vendor_id')` puts the referenced key into `ImportRow::attributes()` (fill-ready for `create()`), and `ImportRow::changes()` holds only the mapped, non-blank values — in Update mode a blank cell keeps the stored value, and the preview diff shows no change for it. `Imports::importers()` describes them for a UI.
- Templates: `Imports::template()` writes a CSV (with a hint row) or an XLSX (bold frozen header, column formats, dropdowns for choice and yes/no columns, an input message per column) with headers in English or Slovak; a filled-in template's leftover hint and example rows (the first two data rows) are skipped on import, while a real row further down that equals the examples imports.
- Dependency-free streaming readers for CSV (UTF-8 with or without BOM, comma or semicolon sniffed or chosen, quoted fields, CR-only files, Excel's `sep=` line) and XLSX (shared strings spooled to disk, every cell type, 1900 and 1904 dates — a plain number mapped to a date field follows the workbook's date system too — read as wall-clock time, DST-change days included, any sheet), available on their own through `Imports::read()`. Other encodings and formats are refused with a message that says what to do.
- Limits on file size, rows and columns; an XLSX row with data below more than `xlsx.max_blank_rows` empty rows rejects the file (`data_after_blank_rows`) instead of being dropped; ZIP and XML hardening (consistency checks, real inflated-byte caps, no DOCTYPE in any part, no entity expansion); reading leaves the process's libxml error mode as it found it (queue workers, Octane).
- Column mapping suggested from headers (names, labels in both locales, aliases, fuzzy matches flagged for review), changeable by header (a header that reads as a number included) or by column number — `ColumnMapping` and the API's `columns` pairs are explicitly by index, and a number that is both a header and another column's index is refused, never guessed — and saved per owner through options-for-laravel — from a session or from header text (`mappings($importer)->save()`), both through `SaveMappingAction` (`SaveMappingData`): the fields are checked, `MappingSaved` fires, and a refused save throws `InvalidSavedMappingException` (422). Saved mappings are recognised whatever the user's locale.
- A preview stored as a resumable session: every row validated (required fields, formats, allowed values, references, duplicates in the file and in the database, and a key only a soft-deleted record holds — flagged `matches_deleted_record` instead of failing at commit), errors per row and cell, counts, update diffs, an error report to fix and re-upload (labels in any locale, `errorReport($format, $locale)`; a file batch's report lists its refused files). Large files validate on the queue with progress; `imports:sweep` fails a validation whose job was lost (`ImportPreviewFailed`, reason `abandoned`), so the session can be previewed again.
- Duplicate modes — skip, update or create new — re-planned without re-reading the file.
- Commit as one Laravel job batch of chunks, each chunk in one transaction with its ledger rows, so a retried or redelivered chunk never writes twice, and a chunk of a batch that is no longer running (failed, abandoned, cancelled) writes nothing; a stopped batch's remaining jobs are cancelled, and a queue that refuses the dispatch fails the commit at once (`dispatch_failed`) and frees the lock; about one query per row (ledger rows are bulk-inserted per chunk, so the ledger model's own Eloquent events do not fire); cancel and resume; `ImportStarted`, `ImportChunkProcessed`, `ImportCompleted` and `ImportFailed` events carrying who, the owner, the counts and the file.
- Undo within a window: created records unchanged since the import (checksum or `updated_at`) are deleted or handed to the importer's rollback hook; changed ones are kept and listed; updates are never reverted. A record undo cannot prove unchanged (no checksum stored, e.g. one the owner query could not read back at commit, which is reported) is kept as `no_checksum`, and each record is row-locked while it is checked and deleted.
- Owner context as a security boundary: every lookup and write stays inside the import's owner, with a pluggable `OwnerScope` (a teams-for-laravel recipe in the docs) and one running import per owner and importer. Every read of a session or batch (status, headers, counts, progress, summary, records, the session list) asks the importer's `authorize()` for `View`, once per handle; a missing batch is reported as a batch.
- File batches (`FileImporter`): many files or a ZIP, one record per file, SHA-256 duplicate checks (a file whose record an undo kept still counts as imported), hardened extraction (file count, size, compression ratio, paths, symlinks, encryption).
- An opt-in JSON API (`imports.routes.enabled`) with FormRequests and resources that never expose class names or file paths; swappable `imports.resources.owner|actor|record`. `GET {prefix}/sessions?importer=&status[]=&per_page=` lists the owner's sessions the user may view, so a client can come back to an open preview. Uploads are rate-limited per authenticated user, or per IP without one (`imports.routes.upload_limit`, 10 a minute, `0` = off).
- `imports:sweep`, `imports:prune`, `imports:doctor`, `imports:importers`, `imports:template` and `imports:install` commands; `about` section. `imports:install` also publishes options-for-laravel's migration (saved mappings live there) unless its table exists, `imports:doctor` checks that table, and a missing one fails with the command that fixes it.
- Session handles answer `isValidating()`, `isPreviewed()` and `isCommitted()`, batch handles `isRunning()`, `isFinished()` and `isRolledBack()`, so a flow can branch on a large file still validating on the queue; `by()` refuses an actor that is not an Eloquent model.
- `Imports::fake()` with an `assert…()` / `assertNo…()` pair for every recorded operation (upload, file upload, map, mode, source, saved mapping save and delete, preview, commit, cancel, resume, rollback, discard, template, error report, prune, sweep), all listed on the facade; `SpreadsheetFactory` builds CSV, XLSX and ZIP uploads in tests.
- English and Slovak translations.
